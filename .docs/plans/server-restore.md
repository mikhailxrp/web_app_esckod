# Восстановление графа чатов и настроек на новом сервере

Что переносится:

| Данные | Файл | В git |
|---|---|---|
| Граф чатов: реплики, переходы | `prisma/data/chat-graph.json` | да |
| Слоты миссий, вопросы и тексты отчёта, подсказки, настройки приложения, тексты блоков ссылок | `prisma/data/game-settings.json` | **нет**, содержит ответы игры, а репозиторий публичный |

Что **не** переносится: пользователи, ключи доступа, прогресс, логи, файлы S3 (аудио, RDP-файлы, картинки блоков ссылок).

## Порядок

Команды выполняются в каталоге приложения на сервере. В `.env` уже должен быть `DATABASE_URL` новой БД, для шага 3 — ещё `ADMIN_INITIAL_EMAIL` и `ADMIN_INITIAL_PASSWORD`.

1. Скопировать файл с настройками (с локальной машины):
   ```bash
   scp prisma/data/game-settings.json <user>@<host>:<каталог приложения>/prisma/data/
   ```
2. Применить схему: `npx prisma migrate deploy`
3. Создать админа и базовые записи: `npm run db:seed` — **один раз, только на этом шаге**.
4. Настройки: `npm run db:settings:sync -- --dry-run`, проверить вывод, затем `npm run db:settings:sync`
5. Граф: `npm run db:chat:sync -- --dry-run`. Ожидается: создать 36, обновить 1, удалить 5 (заглушки из сида), сбросится игроков 0. Затем `npm run db:chat:sync`
6. Проверка: `npm run db:chat:sync -- --verify` и `npm run db:settings:sync -- --verify`
7. Через админку загрузить файлы (список ниже) и ещё раз выполнить `npm run db:settings:sync -- --verify`: предупреждение о файлах должно исчезнуть.
8. Удалить `ADMIN_INITIAL_*` из `.env`.

Шаги 4 и 5 идут именно в таком порядке: граф проверяет триггеры по слотам из БД.

## Нельзя запускать `db:seed` после шага 4

`seedMissionSlots` на каждом запуске перезаписывает слоты заглушками. Если это случилось, повторить `npm run db:settings:sync`.

## Обновить файлы после правок

Отредактировать данные в админке локально, затем `npm run db:chat:export` и `npm run db:settings:export`, закоммитить `chat-graph.json`, заново скопировать `game-settings.json`.
